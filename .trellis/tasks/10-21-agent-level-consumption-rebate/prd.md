# 固定代理等级与按消费结算的两层返利

## Goal

在多级返利（已提交 8a074788d）基础上改为：用户拥有固定代理等级（3 级默认 → 2 级 → 1 级），等级决定能吃到几层返利；返利基数可选「充值」或「消费」（默认消费），消费返利由后台定时结算；等级可手动设置，也可按邀请人数自动升级。

## 业务规则（用户已确认）

### 等级与层级（两层返利）

| 代理等级 | 第 1 层：直属用户自己消费（L1 比例） | 第 2 层：直属用户邀请的人消费（L2 比例） |
|---|---|---|
| 3 级（默认） | 不拿 | 不拿 |
| 2 级 | 拿 | 不拿 |
| 1 级 | 拿 | 拿 |

- 新用户默认 3 级，无论邀请人是谁；3 级邀请人没有任何返利。
- 等级不够拿不到的那一层由平台保留，不往上补发。
- 按结算（或充值）当时的等级计算，升级后不追补历史。
- 最多两层，上一轮的「开放 3 层 / 第 3 层比例」移除。

### 升级

- 升级方式设置：`manual`（仅管理员设置）/ `auto`（邀请人数达门槛自动升）。
- 门槛：升 2 级人数、升 1 级人数；人数口径可配置：全部直属 / 仅有过真实充值的直属（默认全部直属）。
- 自动只升不降。
- 管理员手动降级 → 锁定，不再自动升级；手动升级 → 不锁定；管理员可解除锁定。
- 触发点：绑定邀请人成功后（注册绑定、管理员绑定）评估邀请人；管理端提供「按当前条件重新评估全部用户」。

### 返利基数

- 新设置 `affiliate_rebate_base`：`recharge` / `consumption`，默认 `consumption`。
- `recharge`：沿用现有充值/兑换码/管理员加款入账逻辑，只是加上等级限制、层数上限 2。
- `consumption`：充值不再直接产生返利；后台定时任务按周期汇总每个用户新增的**余额消费**（`usage_logs.billing_type=0` 的 `actual_cost`），沿邀请链发放。
  - 订阅消费不算。
  - 赠送余额不算：每个用户累计计入返利的消费 ≤ 累计真实支付充值（`payment_orders` 完成金额 − bonus − 已退款）。
  - 有效期、冻结期、单人上限（受益人 × 消费用户）照旧生效。
- 历史返利记录不动。

## Acceptance Criteria
- [ ] AC1：3 级邀请人在两种基数下均不入账；2 级只入账第 1 层；1 级入账第 1、2 层；第 3 层不存在。
- [ ] AC2：消费结算幂等：同一批 usage_logs 不会重复发放（水位线 + 领导锁）；受真实充值上限约束；订阅消费被忽略。
- [ ] AC3：auto 模式下绑定邀请人达门槛即升级；手动降级锁定后不再自动升级；手动升级不锁定。
- [ ] AC4：管理端可设置基数、升级方式、门槛、人数口径；可单个/批量设置等级与解锁；专属用户列表与概览显示等级。
- [ ] AC5：用户端显示我的代理等级、各层是否解锁、auto 模式下的升级进度。
- [ ] AC6：后端 gofmt/单元/集成测试、前端 typecheck/test/lint/i18n 通过。

## Out of Scope
- 订阅消费返利；按等级配置专属比例；历史返利按新规则补算。
