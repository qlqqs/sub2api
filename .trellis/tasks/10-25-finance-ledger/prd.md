# 财务明细页

## 分工

- 后端：codex / gpt-6-astra（high）。前端：Claude Opus 5.5（high）。接口以 `contract.md` 为准，任何一方要改契约先改文档。
- e2e、联调、补算 SQL：主会话。

## 背景

一号机（sub2api-custom）需要一个后台页面理清账目：用户充值、消耗、站内剩余余额、赠送余额、代理分润、
账号成本、其他支出，以及总利润和按月 / 按天的利润。现有后台只有分散的统计（首页看板、订单看板、返利页），
且余额是单一资金池，分不清哪部分是付费、哪部分是赠送。

## 统计口径（已与用户确认）

1. **单位**：人民币，1 余额 = ¥1（充值倍率 1）。账号倍率、按张成本都按人民币口径填。日期按北京时间。
2. **利润只来自已消耗的余额**。没消耗掉的余额是预收款（负债），只展示，不算利润。
3. **余额分三类**，统计时按用户、按时间顺序重放，不改扣费流程：

   | 类别 | 来源 | 被消耗时 |
   |---|---|---|
   | 付费余额 | 支付订单本金（`amount − bonus_amount`） | 按该订单单位实收确认收入 |
   | 分润转入 | 代理把分润转入余额（ledger `transfer`） | 按 ¥1 / 单位确认收入（分润产生时已计支出，两边抵消） |
   | 不计收入 | 充值赠送 `bonus_amount`、首充奖励 `invitee_bonus`、优惠码、管理员加余额、非支付兑换码、注册赠送 | 收入 0，成本照记 |

   - 消耗顺序：**不计收入优先**，然后付费余额与分润转入按入账时间先进先出（用户 2026-10-25 确认）。
   - 管理员扣余额：先扣不计收入，再按先进先出扣付费。
   - 退款：从被退订单那一笔里扣；退回的现金从该笔实收里减掉。
4. **订单单位实收** = (`pay_amount` × (1 − 通道费率) − 已退现金) ÷ (本金 − 已扣回余额)。
   易支付通道费率当前 3.2%，以后可能下调：费率配在支付实例上，下单时快照到订单，改费率不影响历史订单。
5. **账号成本**按请求记录，四种方式：

   | 方式 | 例子 | 算法 |
   |---|---|---|
   | 按倍率（默认） | 3、6 号 | 官方价 × 账号倍率（现有公式） |
   | 账号模型倍率（新增） | 2 号 xingwan 个别模型 | 该模型单独的成本倍率替换账号倍率 |
   | 按张 | 4 号 ¥0.05、5 号 ¥0.03 | 渠道「账号统计定价」规则（已在一号机配置，2026-10-25） |
   | 固定成本（新增） | 1 号 vm2api（订阅号池） | 单次请求成本记 0，成本全部来自手工录入的支出 |

   扣费失败、管理员和测试账号的消耗，成本照记；测试消耗的成本单独列一行。
6. **分润**按产生时（ledger `accrue`）计为支出；首充奖励 `invitee_bonus` 属于赠送，不进分润。
   转入余额、提现只是分润的去向，单独展示，不重复计支出。
7. **其他支出**：一期实现手工录入，摊销方式可选「一次性扣除」（当天全额）或「按天摊销」（填天数，订阅账号默认按天 30 天，其他默认一次性），可关联账号；关联了账号的支出在「消耗与成本 → 按账号」里计入该账号的「关联支出」并从毛利扣除（如 vm2api 的订阅费）。
8. **利润** = 已确认收入 − 按量账号成本 − 分润 − 其他支出（摊销后）。

## 需求

### 页面 `/admin/finance`（仅管理员，侧边栏「订单」旁）

- 顶部：日期范围（默认本月）、粒度（日 / 月）。
- **总览**：
  - 期间卡片：已确认收入、账号成本、分润、其他支出、利润、利润率；
  - 当前快照：全站剩余余额（拆成付费 / 分润转入 / 不计收入三类及付费部分对应的实收价值）、冻结余额、未提分润；
  - 趋势图：每日 / 每月的收入、成本、利润。
- **利润明细表**：每行一天（或一月），各列为收入、赠送消耗、账号成本（含内部/测试部分；按成本方式拆分见「消耗与成本 → 按账号」）、分润、支出、利润；可导出 CSV。
- **充值与赠送**：期间实收现金、通道费、退款、到账本金、各类赠送金额；订单明细可下钻到现有订单页。
- **消耗与成本**：按账号 / 分组 / 模型 / 用户拆分的消耗、成本、毛利；按账号的表显示成本方式。
- **分润**：期间新产生（按类型）、转入余额、提现、冻结中、未提余额。
- **其他支出**：增删改查，字段：日期、类别、金额、摊销方式 / 天数、关联账号、备注。
- **用户对账**：每个用户的充值、赠送、分润转入、消耗、退款、理论余额、实际余额、差额；差额不为 0 标红。

## 验收标准

- 本机 e2e 新阶段（FIN 用例）全部通过，金额与 SQL 手算一致（误差 < ¥0.01）：
  - 充值（含通道费）、充值赠送、首充奖励、管理员加减余额、退款；
  - 经网关真实消耗：按倍率、账号模型倍率、按张、固定成本账号各至少一次；
  - 赠送优先的消耗顺序、跨天消耗、余额用完后的收入确认；
  - 分润产生、转入余额再消耗（不重复计）、提现；
  - 其他支出按天摊销跨月；
  - 用户对账在正常数据下差额为 0。
- 不改变任何扣费、转发、调度行为：现有后端单测、e2e p0–p9 全部通过。
- 账号模型倍率未配置时，用量记录的 `account_rate_multiplier` 与改动前完全相同。

## 不在本期范围

- sub2api 自身的订阅套餐收入（一号机未使用）：页面在期间内存在订阅订单时显示提示，不计入利润。
- 兑换码「线下收款」标注：非支付兑换码一律按不计收入处理。
- 历史用量按新规则批量重算成本（本期只在部署时对已知记录做一次性补算，见 implement.md）。
- 付费余额与赠送余额在扣费层面真正拆分。
