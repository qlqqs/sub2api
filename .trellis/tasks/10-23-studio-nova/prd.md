# 创作工作台：嵌入 Nova Studio 生图工作台

## Goal

在 sub2api-custom（一号机站点 QxAPI）里提供一个面向终端用户的生图工作台，降低使用门槛、提高留存：
用户登录本站后直接在网页里生成图片，不需要自己配客户端、Base URL 或复制 Key，花费照常从本站余额扣。

基础是二开开源项目 Nova Studio（fork：`qlqqs/nova-image-studio`，本地 `~/workspace/nova-image-studio`），
不从零自研。选型调研见 `research/selection.md`。

## 用户与场景

- 已登录的普通用户，从侧边栏「创作工作台」进入，生成 / 编辑图片，用对话模型做提示词反推、Agent 规划、网页复刻。
- 管理员只负责部署与开关，不在 Nova 里另配渠道或 Key。

## 范围

### 一期（本任务）

- 生图工作台（文生图、图生图 / 编辑、画布、反推、提示词广场、GIF、Agent、网页复刻），对话模型用于后几项。
- 本站页面 `/studio` 内同源嵌入 Nova，视觉上与控制台无缝（看不出是嵌入的）。
- Nova 设置页里的「模型与密钥」、余额显示、费用预估。
- 账号与数据按 sub2api 用户隔离。
- 本机测试环境接入 + e2e 用例；一号机部署步骤（部署本身需另行征得用户同意）。

### 不在一期

- 视频生成（二期：为 Grok / Seedance 写 Nova 视频插件，必须轮询状态以触发计费；补 CSP `media-src`）。
- 服务端长期历史 / 换设备同步（二期，落 S3）。
- Nova 的浏览器自动化（CDP）—— 永久不在服务器上开启。

## Requirements

### R1 嵌入与部署

- R1.1 Nova 代码只在 `qlqqs/nova-image-studio`，不进入 sub2api 仓库；sub2api 只引用其镜像。该仓库保持公开（AGPL-3.0），`/studio` 页面提供源码链接。
- R1.2 部署为两个独立 compose 项目：`sub2api-custom`（不变的目录结构）与新的 `nova-studio`，通过一个固定网段的共享网络通信；Nova 不映射宿主机端口。
- R1.3 外网入口不变：1Panel 仍只把整个域名反代到 sub2api（18080），1Panel 配置不改。`/_nova/*` 与 `/api/nova/*`（含 WebSocket）由 sub2api 内部转发给 Nova。
- R1.4 sub2api 通过配置开关启用工作台；未配置或 Nova 不可达时，`/studio` 入口隐藏、转发返回 503，其余功能不受影响。
- R1.5 本站页面 `/studio` 在 QxShell 内（保留左侧导航）以同源 iframe 嵌入 Nova。路由不得使用 `/images`、`/videos`（网关已占用）。
- R1.6 无缝呈现：iframe 无边框、占满内容区、只有 Nova 内部一层滚动；Nova 不显示自己的品牌顶栏，背景、字体、间距与控制台一致；随 QxShell 的侧栏收起 / 移动端布局自适应。父页面除 iframe 外不加额外的工具栏。

### R2 账号与身份

- R2.1 不建立 Nova 自己的账号体系；用户无需二次登录、注册。
- R2.2 身份以 sub2api 登录态为准：sub2api 转发时校验 JWT，并向 Nova 注入用户 ID；Nova 只信任经 sub2api 转发来的身份。
- R2.3 sub2api 退出登录或切换账号后，Nova 内存中的 Key 和会话立即失效，不显示上一个用户的数据。

### R3 数据隔离

- R3.1 Nova 服务端的任务、任务结果、生成的图片、WebSocket 订阅、（二期）插件任务与素材都归属用户；非本人访问一律返回 404。
- R3.2 队列状态只返回与本人相关的信息。
- R3.3 Nova 侧不对用户设额外限额（不限每日任务数、并行张数、并发数、存储占用）；Nova 原有按 IP / Key 的限流与排队上限在嵌入模式下关闭或放宽到不影响正常使用。用户仍受 sub2api 网关自身的限制（用户并发、RPM、Key 额度与余额），这部分不变。服务端全局任务并发（`NOVA_TASK_CONCURRENCY`）作为容量参数保留。
- R3.4 服务端图片与任务保留 7 天（可配置），到期清理。
- R3.5 浏览器本地存储（模型配置、Agent 会话、画布素材、历史）按用户 ID 分区；切换账号后看不到他人本地数据。
- R3.6 提示词广场为公共只读内容，不需隔离；来源文件与示例图由 Nova 后端按固定白名单拉取并缓存，浏览器不访问第三方（契约 §8A）。

### R4 固定网关地址

- R4.1 用户界面不出现 Base URL 与自填 Key 的入口（BYOK 设置、备份导出 Key 均锁定）。
- R4.2 Nova 后端忽略任何来自客户端的 baseUrl / `x-nova-base-url`，所有上游请求一律走内网网关地址；不允许直连 api.openai.com、api.x.ai、Google、Anthropic 等任何其他地址（插件 `defaultBaseUrl`、`/api/nova/proxy/*` 同样适用）。
- R4.3 Nova 调网关时携带用户真实 IP（`X-Forwarded-For`），sub2api 只信任共享网络网段，使 Key 的 IP 白名单、风控、使用记录中的 IP 保持正确。

### R5 模型与密钥（Nova 设置页）

- R5.1 Nova 设置页的「模型与密钥」分区（替换 Nova 原有的自定义模型 / BYOK 分区）；分「生图 / 对话 / 视频」三行，每行「选 Key → 选模型」。视频行一期显示为「即将上线」不可选。
- R5.2 Key 下拉只列出当前用户自己的 sub2api Key，并按用途过滤：生图要求 Key 所属分组支持生图（平台与 `allow_image_generation`），对话不限平台。禁用、过期、额度用完的 Key 置灰并说明原因。
- R5.3 模型下拉来自所选 Key 在网关上实际可用的模型，按用途分类；请求协议由分组平台自动推出，用户不选。
- R5.4 显示所选模型在该分组下的单价，格式与模型广场一致，不显示「倍率」字样。
- R5.5 没有可用 Key 时提供「一键创建」：从用户可用分组中选择后创建 Key 并自动选中。
- R5.6 记住每行的选择，只保存 Key ID 与模型名（按用户分区），不保存 Key 明文；明文每次从 sub2api 读取，只在内存中。
- R5.7 同一把 Key 可用于多行，也可不同。
- R5.8 首次进入且未选择时，自动打开设置页并定位到该分区；生图前缺少生图 Key 时给出提示并可一键打开设置。

### R5A 设置页其他分区

- R5A.1 去掉「关于」分区。AGPL 要求的源码链接改放在设置页底部（小字链接到 `qlqqs/nova-image-studio`）。
- R5A.2 「插件」分区只对 sub2api 管理员账号显示；Nova 后端若有插件相关的管理类接口，同样只允许管理员调用（以 sub2api 注入的角色为准，不信任前端）。
- R5A.3 「备份」分区保留，但导出内容不含任何 Key。

### R6 余额与费用

- R6.1 余额只显示在控制台顶栏（Nova 内不重复显示）；每个任务结束后 Nova 通知父页刷新。
- R6.2 提交前展示预估费用（单价 × 张数 / 规格），以模型广场价格为准；按 token 计费的模型不预估。
- R6.3 余额不足、限流、内容审核、Key 失效等网关错误转为中文提示；余额不足时提供「去充值」入口。
- R6.4 计费仍完全由 sub2api 网关按所选 Key 完成，不存在第二套余额或积分。

### R7 UI 风格

- R7.1 Nova 整体换成 QxAPI 风格：主色群青蓝 `#2340D0`、极简线条（1px 细线、少大块底色），以修改主题变量为主。
- R7.2 去除 Nova 品牌、赞助、桌面端入口、BYOK 设置、「关于」；保留其模式导航与手机 / 平板 / 桌面三端布局。
- R7.3 深色 / 浅色跟随本站设置。
- R7.4 文案中文为主（Nova 原生无 i18n）；英文界面一期不做。

### R8 功能开关

- R8.1 一期开放：生图、图生图、画布、反推、提示词广场、GIF、Agent、网页复刻。
- R8.2 一期关闭：视频工作台、CDP 浏览器自动化（环境变量与界面均关闭）。

## 约束

- 改动集中在 sub2api 的 fork 自有文件，上游文件只做一行挂接，保持与 Wei-Shaw/sub2api 的可合并性。
- Nova 侧改动集中在嵌入接入层与主题文件，尽量不动核心组件，保持与 tianjiangqiji/nova-image-studio 的可合并性。
- 先在本机测试环境（`~/workspace/sub2api-local`）验证全部通过，再经用户同意提交、推送、部署一号机。
- 本机环境的隔离规则不变：只监听 127.0.0.1、名称不与其他部署冲突、禁止全局 Docker 清理。

## Acceptance Criteria

- [x] 登录用户在 `/studio` 无需任何额外配置即可生成图片；生成结果的扣费与 usage 记录与直接调 API 一致（同 Key、同模型、同张数、同金额）。 （e2e STU-00..05）
- [x] 用户 A 拿到用户 B 的任务 ID / 图片链接 / WebSocket 订阅均得到 404 或无数据。 （STU-08..10；WebSocket 由 Nova 后端测试覆盖）
- [x] 同一浏览器切换账号后，看不到上一个账号的 Key、会话、本地历史。 （`studio_ui.cjs switch`：B 看不到 A 选的 Key，本地存储按用户分区）
- [x] 构造客户端 baseUrl / `x-nova-base-url` 指向其他地址（含官方地址、内网地址）时，Nova 不向该地址发起任何请求。 （STU-02/07；请求头与内网地址由 Nova 后端测试覆盖）
- [x] 网关 usage 记录中的客户端 IP 为用户真实 IP，而不是 Nova 容器 IP；Key 的 IP 白名单对工作台请求生效。 （STU-06）
- [x] Nova 设置页「模型与密钥」按用途正确过滤 Key 与模型；单价与模型广场一致；无 Key 时可一键创建。 （Nova 前端测试 + 界面联调）
- [x] 设置页没有「关于」；普通用户看不到「插件」，管理员可见；普通用户调用插件管理类接口被拒绝。 （STU-12 + 界面联调）
- [x] `/studio` 视觉上与控制台无缝：无 iframe 边框、无双层滚动条、无 Nova 品牌顶栏，截图经用户确认。 （2026-10-24 用户看过截图后进入阶段 4）
- [x] 余额不足时给出中文提示与充值入口。 （界面联调：任务卡「账户余额不足，请充值后重试」+ 提示条「去充值」）
- [x] 未配置 Nova 时 `/studio` 入口隐藏、`/_nova`、`/api/nova` 返回 503，原有 e2e（p0–p6）全部通过。 （后端单测 `TestStudioProxy_DisabledReturns503`；Nova 停机 503 见 STU-16；run_all 309/309）
- [x] `/_nova` 页面能在 `/studio` 中正常加载（iframe 不被 X-Frame-Options / CSP 拦截），其余页面的安全响应头不变。 （STU-11；后端单测 `TestStudioProxy_OtherPathsUntouched`）
- [x] Nova 界面为 QxAPI 风格，截图经用户确认。 （极简配色：控制台 token、1px 淡线、深浅色跟随；2026-10-24 用户确认）
- [x] 视频入口与 CDP 不可用。 （STU-13）
