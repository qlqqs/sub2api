# 注册赠送按邀请来源筛选

## 目标

管理员通过下拉框选择哪些邀请来源可获得注册赠送；注册页和邀请页展示与当前设置一致的赠送金额。

## 背景与证据

- 当前注册赠送统一读取 `affiliate_invitee_signup_bonus`，不区分邀请来源（`backend/internal/service/affiliate_owner.go:205`）。
- 绑定时已有 `InviterWasAgent` 快照（`backend/internal/service/affiliate_owner.go:150`），代理判定已有 `isAgentLevel`（同文件:134）。
- 管理后台已有金额卡片（`frontend/src/views/admin/SettingsView.vue:8082`）。注册页目前只依据公开金额和邀请链接显示（`frontend/src/views/auth/RegisterView.vue:609`）；我的邀请页金额来自 detail（`backend/internal/service/affiliate_detail.go:66`）。
- 上一任务 `.trellis/tasks/archive/2026-10/10-27-invitee-signup-bonus/prd.md` 定义的余额、赠送分类与幂等口径继续沿用。

## 已确认需求

- R1：新增「邀请来源」下拉框：全部邀请 / 代理邀请 / 普通用户邀请。两种来源共用一个赠送金额，不分别配置金额。缺省为全部邀请，兼容现有行为。
- R2：分类只看直接邀请人。普通用户即使归属代理，仍属普通用户邀请。实际发放按注册绑定时身份判断，本次邀请导致的后续自动升级不改变分类；未来身份变化不追溯历史。
- R3：只在符合来源的注册绑定成功后发放；金额为 0 或总开关关闭时不发放。邮箱及 OAuth 注册一致。保留每人最多一次、补绑不发放、失败不阻断注册的既有行为。
- R4：注册页和我的邀请页读取当前设置，页面重新加载时更新，不做实时推送。来源不匹配或金额为 0 时隐藏赠送提示。实际新注册按发放时当前金额执行；已领取金额及历史流水保持原值。
- R5：UI 使用下面的简短文案，不增加补绑、快照、异常情形等防御性说明；同步英文翻译。

| 位置 | 文案 |
|---|---|
| 后台标题 | 被邀请人注册赠送 |
| 后台说明 | 通过邀请注册的新用户可获得余额赠送。 |
| 下拉标签 | 邀请来源 |
| 选项 | 全部邀请 / 代理邀请 / 普通用户邀请 |
| 金额标签 | 赠送金额（¥） |
| 金额提示 | 0 表示不赠送 |
| 我的邀请 | 好友通过你的邀请注册，即得 ¥{金额} 余额 |
| 注册页 | 通过邀请注册，即得 ¥{金额} 余额 |
| 历史记录 | 沿用现有「注册赠送」名称，不增加来源标签 |

## 范围外

不改代理分润、普通邀请返利、首充奖励、赠送的财务分类；不做历史补发/追回、分来源金额或统计、实时推送。本任务无自动提交、推送、远端部署授权。

## 验收标准

- AC1（R1/R3）：三种选项分别与代理/普通用户邀请交叉验证，共六种场景，发放结果符合选择；保存并重新加载能恢复选项。
- AC2（R2）：归属代理的普通用户邀请按普通用户分类；邀请触发升级时按绑定快照分类。
- AC3（R3）：覆盖邮箱及 OAuth、无效/缺失邀请码、总开关关闭、金额为 0、补绑、重复和并发，且不破坏首充叠加与原幂等。
- AC4（R4/R5）：后台把金额从 5 改为 10 后，刷新相关页面显示 10，新注册发 10，历史领取 5 不变；切换来源后对应提示显示/隐藏。
- AC5（R4/R5）：注册页无效邀请不展示赠送提示；加载或查询失败不展示误导性金额，也不新增错误说明；邀请码变化时不残留上一个邀请的提示。
- AC6：相关后端单元/集成测试、前端 lint/typecheck/test、构建及本机隔离环境 e2e/UI 验证通过，无锁文件意外变更。
