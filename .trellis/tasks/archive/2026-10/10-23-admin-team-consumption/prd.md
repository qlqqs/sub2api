# 管理端团队消费页

## Goal

管理员在后台按代理查看所选时间段的团队余额消费与分润：一页看清代理渠道整体带来了多少消费、付出了多少分润、哪些代理贡献最多；点进任一代理，看到的与该代理自己打开「团队消费」页时完全一致，并能逐层下钻到二级团队和单个客户的请求明细。界面见 `ui.md`（2026-10-23 用户确认），技术方案见 `design.md`。

## Background

- 代理端团队消费页已完成并提交（`196ee2502`、`b62bc1536`，任务 `10-22-agent-team-consumption`，未推送）。其 PRD 把「管理端查看某代理视角的页面」列为不做，本任务补上。
- 后台现状（2026-10-23 核对）：
  - 仪表盘有全站趋势、模型分布、用户消费榜，不按代理归组。
  - 使用记录一次只能筛一个用户；支持 `?user_id=&start_date=&end_date=` 直达（`frontend/src/views/admin/UsageView.vue:321`）。
  - 代理管理列表的「累计分润」是全部历史之和，不能选时间段、不能排序（`backend/internal/repository/affiliate_repo.go:1682`）；「查看客户」弹窗只有贡献分润，没有消费。
  - 后台没有「以用户身份登录」，管理员打不开代理的团队消费页。
  - 现有管理端邀请返利接口不检查功能开关；侧边栏「邀请返利」分组随功能开关显示。
- 可复用：用户日汇总 `usage_user_daily_rollups`（迁移 251）；`AffiliateTeamService` 全部查询以 `viewerID` 为根（`backend/internal/service/affiliate_team.go:259`）；前端 `AffiliateTeamView.vue` 与 `components/user/affiliate-team/*`。
- 规模预估同代理端：2 万用户、2 千活跃。

## Requirements

### R1 准入与入口
- 仅管理员可访问。与其他管理端邀请返利接口一致，后端不检查邀请返利功能开关。
- 侧边栏「邀请返利」分组新增「团队消费」，排在「代理管理」之后。
- 代理管理列表「⋯」菜单新增「团队消费」，直达该用户的代理视角；仅对一级 / 二级代理或有归属客户的用户显示。

### R2 汇总页收录范围
- 每行一个「有团队的人」，与代理端准入一致：当前一级 / 二级代理，以及已降级但名下仍有快照客户（`agent_owner_id` 或 `agent_upline_id` 指向他）的用户。账号已删除的也列出，显示「已删除」与用户 ID，可点进查看其名下客户。
- 按等级计数并可筛选：全部、一级、二级、已降级（无已降级时不显示该项）。
- 搜索：邮箱、昵称模糊匹配，用户 ID 精确匹配。

### R3 指标口径
- 消费、请求、活跃客户、时间范围与代理端 PRD R3 相同：余额消费（`billing_type = 0`）的 `actual_cost`，北京时间自然日。
- 每行（代理 X）：
  - 团队消费、活跃 / 客户：等于 X 自己页面摘要条上的「消费」「活跃客户」，团队 = `agent_owner_id = X OR agent_upline_id = X`。一级代理的数字包含其二级团队，一级与其二级的行有重叠，列不可相加（用户确认的口径）。
  - 分润：等于 X 自己页面摘要条上的「收益」，即时间范围内入账、来源仍在其团队中的 `agent_direct` + `agent_diff`。
- 汇总条：
  - 消费：所有有归属代理（`agent_owner_id` 非空）的客户的消费，每个客户只算一次；附「占全站余额消费 x%」。
  - 分润：时间范围内入账的全部代理分润，不限来源；附「占团队消费 x%」。来源已离开受益人团队的分润（如被改挂走的二级在改挂前的消费）计入这里，不计入各行，所以各行分润之和可能略小于汇总。
  - 活跃客户：上述客户中时间范围内有消费的人数 / 总人数（含已删除账号，与代理端客户数一致）。
  - 消费列的比例条以汇总条「消费」为分母。
- 趋势（每日消费与分润）、模型分布（前 5 + 其他）的范围与汇总条一致。

### R4 代理视角（下钻）
- 摘要、趋势、模型、直属客户、下级代理、二级团队、客户详情与请求明细的范围和数字，与该代理自己打开团队消费页时完全一致（同一套服务代码，以被查看的代理为根）。
- 与代理端的差异只在展示：
  - 邮箱完整显示；搜索支持邮箱 / 昵称模糊、ID 精确。
  - 每层显示被查看对象的用户 ID；根页元信息行显示等级、上级（二级代理，可点进上级视角）、累计分润（全部历史，与代理管理列表一致）。
  - 文案改为第三人称，见 `ui.md` 第 4 节。
  - 客户详情提供「使用记录」链接，跳到管理端使用记录并带上该用户与当前日期范围。
- 不提供任命 / 取消、改等级等操作。

### R5 隐私与字段
- 团队接口的字段集合与代理端一致（不返回余额、充值、IP、UA、API Key、上游账号等），只是邮箱不脱敏；完整明细经「使用记录」在既有页面查看。
- 代理端接口的响应不变（管理端新增字段只在管理端出现）。

### R6 时间范围
- 与代理端相同：默认最近 7 天，最长 90 天，后端同样校验。

### R7 性能
- 汇总页不得扫描 `usage_logs` 明细，也不得扫描时间段内的全部分润流水；本机按 2 万用户、2 千活跃（全部为渠道客户）、分润流水按每小时结算造数，90 天范围下汇总页各接口 < 1s。
- 限流沿用管理端路由组的全局限流，不加重型限流（与管理端仪表盘、使用记录一致）。

## Acceptance Criteria

- [x] AC1 准入：未登录 401、非管理员 403；侧边栏与代理管理「⋯」菜单入口按 R1 显示。
- [x] AC2 收录：构造一级、二级、已降级有老客户、已删除、普通用户，汇总页只列出前四类；等级计数与筛选正确；搜索邮箱片段、昵称片段、完整 ID 命中，`%` `_` 不作通配。
- [x] AC3 汇总口径：汇总条、趋势、模型分布与直接对 `usage_logs` / ledger 的 SQL 汇总一致；一级与其二级都有消费时，汇总条消费等于去重后的客户消费之和；全站占比的分母正确；分润不限来源。
- [x] AC4 每行一致：任一代理行的团队消费、活跃 / 客户、分润，与该代理调用代理端 `overview` 接口得到的值相同（含存在已离开团队的来源时）。
- [x] AC5 代理视角一致：同一代理、同一时间范围，管理端下钻各层接口的数字与代理端接口逐项相同，邮箱为完整形式；代理端接口响应不含管理端新增字段。
- [x] AC6 下钻与返回：汇总页 → 代理视角 → 二级团队 → 客户详情 → 使用记录，各层面包屑、ID、上级链接正确；面包屑首项回到汇总页时恢复离开前的筛选、排序、页码；浏览器返回恢复上一层状态。
- [x] AC7 时间范围：超过 90 天被拒绝；切换后汇总、图表、表格一致刷新。
- [x] AC8 分润汇总表：插入、删除、级联删除、来源置空、解冻更新、跨北京时间零点、回填与重建后，与直接对 ledger 重算一致；汇总出错不影响流水写入。
- [x] AC9 性能：满足 R7，结果写入 `research/perf.md`。
- [x] AC10 后端 gofmt / vet / 单元 / 集成测试，前端 lint / typecheck / vitest / i18n / build 全部通过；代理端原有测试与 e2e（206 条）全部通过；本机 e2e 覆盖管理端页面并截图。

## Out of Scope

- 导出 CSV、自动刷新、环比 / 同比。
- 在该页任命、取消、改等级或改归属（仍在代理管理页操作）。
- 客户余额、充值金额、订阅消费。
- 代理管理列表的「累计分润」列与「查看客户」弹窗保持不变。
- 代理端查询改读分润汇总表（`design.md` 第 9 节，以后可选）。
