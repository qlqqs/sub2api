# 上游同步与增量合并工作流

## 目标

维护一个干净、可核对的上游镜像 main，并按需将通用维护修复集成到 sub2api-custom。持久保存逐项审查决定与实际集成证据，让下次只审查新增内容和满足重开条件的旧条目，而不是重复翻阅已审查提交。

## 背景与已确认事实

- 用户已明确要求使用子代理，并于 2026-10-27 同意创建本任务；任务创建不代表实施、提交、推送或部署批准。
- 用户明确排除模型上新、Terra 适配及模型更新工作流，这些由其他任务处理。
- 创建任务时 custom HEAD 为 `98894b242c672937173f5af630eb65e68c565c6d`；本地 main 与缓存 origin/main 为 `8f2cbb53d9d1c40e1865b07ac460571f7d4c48de`，缓存 upstream/main 为 `dba770d56a0ee0ae5bad1b3dc5e11614d323163c`。
- 前序 GitHub 只读核查于 2026-10-27 观察到 upstream main `ba81c7fd758e425d67f856d601147ef0c5263d3f`；尚未 fetch，实施时重新冻结目标，不把缓存引用当作远端当前状态。
- 当前工作区有其他并行任务的未提交变动；本任务不拥有这些文件。历史审查快照为 69 项变动，不以此数量判断后续是否干净。
- 已有 journal 批次记录，没有能区分审查、选入、验证和落地的逐提交台账。证据详见 `research/progress-ledger-design.md`。

## 需求与边界

### R1 — 上游镜像
- main 只跟随上游已合并历史，不放本项目定制代码、任务文档或台账。
- 只允许快进同步；发现本地分叉、上游改写历史或 main 被其他工作区占用时停止自动处理，保留现场。
- 同步 main 不等于把其全部变化合入 custom，也不等于已推送 origin/main。

### R2 — 选择性维护集成
- 首批拟选：安全依赖/构建版本链、模型限流快照写时复制（通用并发修复）、Cloudflare 1010 错误分类、queued/metadata 后的安全重试修复。
- 每项选入需有源提交、依赖说明、定制兼容性审查和验证证据，按依赖顺序处理。
- Anthropic 断流计费二提交组合保留为后续独立验收批次，本次先记录审查结论，不默认实施。
- 不整包移植 Codex 身份改动或 Retry-After 策略；不改变既有图片计费开关、管理员权限或备份恢复行为。
- 保留定制 Node 构建设置、客户端模型名、citations、图片流回填、财务和分润行为。非当前 custom 镜像入口的 Dockerfile 版本统一暂缓，需另列审查，不顺带扩大本批范围。

### R3 — 可持续增量审查
- 分开记录远端获取位置、连续审查位置与 custom 实际集成状态，不用一个 SHA 代表三者。
- 已审查但暂缓/不采用的内容有理由、依赖和重开条件；不能因暂缓而永远从待办中消失。
- 审查覆盖 main 的实际增量，包括 merge resolution；不把 merge commit 与其子提交重复算成不同功能。
- 记录源 SHA 到目标 custom SHA 的映射；部分摘取、等价实现、回退均可追踪。patch-id 只能辅助判断，不单独证明语义等价或测试完成。
- 未合并 PR 不属于 main 审查游标；记录精确 head/base，变化后仅复审增量和影响，合并后核对最终差异。
- 模型类提交在本任务中只记录“移交模型任务/本范围不实施”，不审查其能力、价格或接入实现，也不虚构已完成模型专项审查。

### R4 — 隔离、验证和授权
- 使用独立候选工作区，不 checkout/stash/reset/覆盖当前 custom 工作区，也不清理他人的失效 worktree。
- 已应用候选、已通过测试、已进入 custom、已推送、已部署是不同事实，必须分别报告。
- 候选测试不能替代与并行任务合流后的最终回归；custom 基线变化需要重新整合与验证。
- 本机环境测试须串行占用；不触碰一号机和其他项目。提交、推送、部署均另获同意。

### R5 — 收尾更新现有记录文档
- 每轮最后必须核对并更新现有记录，而非只新增报告：长期 state/decisions、本轮任务状态与验证记录、开发 journal 及索引，以及被本轮行为变化影响的现有规范/运维说明。
- 明确记录同步前后 SHA、逐项结果、验证目标与结果、未完成项、暂缓原因、下一轮审查起点及提交/推送/部署实际状态。
- 历史证据和追加事件不改写为新结论；用新事件或补充记录纠正。没有部署时不改变现有生产版本记录。
- 本轮收尾报告列明已更新的文档路径；检查后无需修改的相关文档注明原因。未完成记录同步不能宣称该轮收尾完成。

## 验收标准

- [x] AC1/R1：获批实施后，本地 main 与冻结的上游目标 SHA 一致，且未引入本项目定制提交；无强制覆盖或未获批推送。
- [ ] AC2/R2：首批四组维护修复的选入/适配及依赖有记录，必要测试通过；不以补丁无冲突替代行为验证。
- [x] AC3/R3：冻结范围内每个审查单元都有可解释的决定，审查游标不能越过未处理缺口；模型类移交记录明确标注未做专项审查。
- [ ] AC4/R3：同一目标重复生成队列不重复列出已审查且无需重开的单元；新增上游提交、PR 改版、暂缓项满足条件时能正确进入队列。
- [x] AC5/R3：每个实际集成项能追到源 SHA、目标 SHA、变更范围及验证证据；未提交候选不得误记为已集成。
- [x] AC6/R4：原工作区他人改动被保留；本机定向检查、构建及受影响业务回归有记录；最终集成受原工作区状态与授权约束。
- [x] AC7/R1–R4：更新规范、进度台账和增量查询步骤可从项目规范索引找到，下一次可独立恢复执行。

- [x] AC8/R5：收尾已同步现有台账、任务记录、journal/索引及受影响规范；文档间版本与状态一致，已列出更新路径或无需更新的原因，未虚报提交/部署。

## 不在范围内

模型上新/适配与相关工作流；未合并 PR 的自动引入；全量升级上游业务功能；真实付费推理；自动提交、推送或部署；修复既有响应模型观测缺口；修改已执行迁移或财务历史数据。
