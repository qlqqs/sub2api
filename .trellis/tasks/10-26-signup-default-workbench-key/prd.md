# 新用户默认稳定分组 Key 与工作台开箱即用

## 目标
新注册用户无需手动创建 Key、选择分组并分别配置工作台，即可在具备余额与模型可用条件时使用创作工作台和对话工作台。

## 需求
- R1：绑定当前部署中名为「Codex 稳定分组」的既有分组，核实其 ID 后为每个新注册用户生成一个绑定该 ID、属于该用户的 Key。用户明确指定现有目标，不新增后台分组选择配置。
- R2：Key 名称取该 ID 对应的分组名称；「Codex 稳定分组」是当前指定目标，Key 名称不是独立的硬编码常量（2026-10-26 用户进一步明确，取代固定名称表述）。
- R3：新用户首次进入创作工作台或对话工作台时，查找与目标分组名称同名的 Key；存在则默认配置，不存在则提示配置 Key，不在此时补建。匹配还必须验证归属、group_id 与可用状态，防止同名异组误选。
- R4：创作／生图工作台在账户余额不足时展示「账户余额不足，请充值后重试」，不以原始 403 作为用户提示；与对话工作台的充值引导保持一致。不能把非余额原因的所有 403 都转换成充值提示。
- R5：用户指定默认文本模型为 `gpt-6.1-sol`，思考强度 `medium`（2026-10-26）；创作工作台文本用途如何传递强度需核查。
- R6：默认生图模型沿用 `gpt-image-2.5-sunburst`（2026-10-26 用户确认）。
- R7：目标分组没有指定默认模型时，提示「默认模型不可用，请选择其他模型」，不静默切换为其他模型（2026-10-26 用户确认）。
- R8：默认 Key 创建失败不阻断注册；进入工作台时无匹配 Key 则按 R3 提示配置（2026-10-26 用户确认）。
- R9：每个工作台只做首次初始化；之后用户换 Key、换模型或主动清空配置，都保留其选择，不在下次进入时自动覆盖（2026-10-26 用户确认）。
- R10：自动创建必须幂等；继续遵循原有权限、Key 状态、余额与计费规则，不赠送额外余额、不绕过分组访问限制。

## 范围
- 面向新注册用户，覆盖邮箱注册及第三方登录首次创建账户的注册路径。
- 两个工作台分别进行首次初始化；默认配置不依赖工作台在注册时在线。
- 修复创作工作台余额不足错误展示，适用于新老用户的相关错误路径。

## 不在本次范围
- 不批量给存量用户补 Key，不迁移或覆盖存量工作台配置。
- 不扩展到管理员手工创建用户，不新增后台默认分组选择器。
- 不自动重建被删除 Key，不自动重命名已有 Key，不自动更换不可用模型。
- 不修改计费政策，不自动执行历史重算；提交、推送、部署须另获同意（2026-10-26 已获授权）。

## 验收标准
- AC1（R1/R2）：新注册用户拥有绑定指定分组 ID 的默认 Key，名称等于创建时该分组的名称，归属正确。
- AC2（R3）：满足余额与模型可用条件时，首次进入两个工作台无需手动配置 Key 即可完成一次对话和一次生图。
- AC3（R3）：工作台间及账号间不串用 Key，原有归属与状态校验继续生效；同名异组 Key 不能误选。
- AC4（R3）：首次进入无匹配 Key 时提示配置 Key，不悄悄补建或选择其他分组。
- AC5（R4）：真实余额不足的生图失败展示充值提示；非余额原因的 403 不误报为余额不足。
- AC6（R5）：默认文本模型为 `gpt-6.1-sol`，思考强度为 `medium`；验收应检查实际请求参数，不能只检查界面标签。
- AC7（R6）：目标分组支持时，默认生图使用 `gpt-image-2.5-sunburst`。
- AC8（R7）：指定默认模型不在目标分组可用模型中时，明确提示用户选择其他模型，不静默替换，也不以付费请求探测可用性。
- AC9（R8）：模拟默认 Key 创建失败后，注册仍成功，工作台在无匹配 Key 时提示配置，不因辅助初始化失败返回注册失败。
- AC10（R9）：首次初始化后修改 Key、模型或清空配置，重新进入两个工作台都不恢复系统默认选择；已有人工配置不被覆盖。
- AC11（R10）：注册重试及并发初始化不会重复生成默认 Key；无分组权限、Key 停用、过期与额度耗尽仍执行原有校验。
- AC12（范围）：存量用户不被批量补 Key 或覆盖配置；余额不足提示修复不受注册时间限制。
