# 代理团队消费页

## Goal

代理在独立页面查看归属自己的客户、下级代理团队的余额消费和给自己带来的收益，并能逐层下钻到单个客户的请求明细。被降级但仍有老客户的用户同样可以查看。界面见 `ui.md`。

## Background

- 代理身份只看 `user_affiliates.agent_level`（1 一级 / 2 二级 / 3 普通）。分润按绑定时冻结的快照：`agent_owner_id`（归属代理）、`agent_upline_id`（归属代理为二级时其上方一级），见迁移 248/249 与 `archive/2026-10/10-21-two-tier-agent-reward`。
- 现有用户端 `GET /user/aff` 只返回直属邀请人列表（上限 100、无分页，`backend/internal/service/affiliate_service.go:31`），不含任何消费金额。
- 消费数据在 `usage_logs`：`actual_cost` 为扣费（显示 ¥），`billing_type=0` 为余额消费；有 `(user_id, created_at)` 索引，没有按用户的汇总表。
- 收益流水 `user_affiliate_ledger`：`user_id` 受益人、`source_user_id` 消费者，代理分润 `reward_type` 为 `agent_direct` / `agent_diff`；消费按结算周期入账（默认 60 分钟，`backend/internal/service/domain_constants.go:92`）。
- 后台已有同口径查询 `ListAgentCustomers`（`backend/internal/repository/affiliate_repo.go:1723`）；邮箱脱敏 `maskEmail`（`affiliate_service.go:578`）。
- 规模预估：2 万用户、2 千活跃。

## Requirements

### R1 准入
- 可访问：当前为代理（等级 1/2），或存在 `agent_owner_id = 我` / `agent_upline_id = 我` 的快照客户（被降级者看老客户）。
- 其他用户、或邀请返利功能关闭时：入口不显示，接口拒绝。
- 所有接口以当前登录用户为根限定范围；访问范围外的代理或客户一律按「不存在」处理。

### R2 范围（全部按归属快照，不按邀请关系）
- 我的客户：`agent_owner_id = 我`，含我下面二级代理本人。
- 下级代理：当前 `agent_level = 2 且 agent_owner_id = 我` 的用户，∪ 所有 `agent_upline_id = 我` 的客户的归属代理。后者中已不再是我当前二级的（降级、转挂其他一级、升级）标记为「历史」。
- 某二级代理 X 的团队：`agent_owner_id = X 且 agent_upline_id = 我`。二级代理本人的消费只计入「我的客户」，不在其团队中重复。
- 团队合计 = 我的客户 ∪ 全部下级团队（`agent_owner_id = 我 OR agent_upline_id = 我`）。

### R3 指标口径
- 消费：`usage_logs.billing_type = 0` 的 `actual_cost` 之和；时间按北京时间自然日。订阅消费不统计、不显示。
- 请求：上述记录条数；Token：输入 + 输出 + 缓存写入 + 缓存读取。
- 收益：`user_affiliate_ledger` 中 `user_id = 我`、`reward_type ∈ (agent_direct, agent_diff)`、来源在范围内的金额之和，按入账时间落入时间范围；累计收益不限时间。
- 活跃客户：时间范围内消费 > 0 的客户数。
- 最近使用：客户最近一次余额消费时间（明细保留期内，默认 90 天）。
- 页面只按消费口径设计，不为「按充值返利」模式做适配。

### R4 展示与隐私
- 客户显示「昵称 + 脱敏邮箱」；昵称取 `users.username`，为空显示 `-`；账号已删除显示「已删除」。
- 不向代理返回：余额、充值金额、IP、UA、API Key、上游账号、上游实际模型、费用拆分与倍率、请求 ID / 会话 ID。
- 搜索：昵称模糊匹配，邮箱只做完整精确匹配（避免按前缀逐位反推脱敏邮箱）。

### R5 请求明细（单个客户）
- 字段：请求时间、模型（用户请求的模型名，与用户自己的使用记录页一致）、分组名、Token（输入 / 输出 / 缓存写入 / 缓存读取；生图、视频按张数 / 条数显示）、扣费 ¥。
- 筛选：模型、分组；按时间倒序分页。

### R6 时间范围
- 默认最近 7 天，最长 90 天，与 `usage_logs` 默认保留期一致（`dashboard_aggregation.retention.usage_logs_days`）；后端同样校验上限。

### R7 性能
- 多客户聚合（总览、客户列表、下级代理列表、趋势、模型分布）不得直接扫描 `usage_logs` 原始明细，需走按用户按日的汇总数据，且数据实时（不依赖定时任务的延迟）；单客户请求明细走 `(user_id, created_at)` 索引。
- 新接口挂 `.Heavy()` 限流。

### R8 入口：「邀请 | 团队消费」标签
- 邀请返利栏目下两个标签：邀请（`/affiliate`）、团队消费（`/affiliate/team`），共用顶部栏标题与说明；有团队消费权限（`team_access`）时才显示标签栏，普通用户只有邀请页。侧边栏不加菜单。
- 团队消费标签行右侧放日期与刷新；下钻页（二级团队、客户）用面包屑代替标签栏。

### R9 邀请列表：昵称、搜索、分页
- 邀请列表增加「昵称」列（为空显示 `-`），邮箱仍为脱敏；可按昵称模糊或完整邮箱精确搜索（与团队页一致）；服务端分页（每页 20）。
- 新增 `GET /user/aff/invitees?search&page&page_size`；`/user/aff` 不再内嵌最多 100 人的邀请列表。
- 目的：一级代理能在数千直属用户中找到要任命为二级的人。

## Acceptance Criteria

- [x] AC1 准入：一级、二级代理可进入；有快照客户的普通用户可进入并看到降级提示；无快照客户的普通用户入口不显示、接口拒绝；功能关闭时同样拒绝。
- [x] AC2 范围：构造「一级 B、二级 A（上级 B）、A 的客户、B 的直属客户、普通用户再邀请的客户、成为代理前邀请的归属他人的用户」，B 的「我的客户」「下级代理」「A 的团队」和 A 的「我的客户」与 R2 完全一致；A 本人消费只出现在 B 的「我的客户」中。
- [x] AC3 历史二级：A 被降级或改挂其他一级后，B 的下级代理列表仍显示 A（标记「历史」），A 的老客户消费与差额收益照常统计。
- [x] AC4 口径：订阅消费不计入；消费、请求、Token、收益、活跃客户与直接对 `usage_logs` / ledger 的 SQL 汇总一致（含今天的实时部分）。
- [x] AC5 越权：访问范围外的二级代理 / 客户 ID、伪造参数，均返回「不存在」且不泄露任何数据。
- [x] AC6 隐私：接口响应中不含 R4 列出的字段；邮箱均为脱敏形式；邮箱前缀搜索无结果。
- [x] AC7 明细：生图请求显示张数；模型、分组筛选生效；分页正确。
- [x] AC8 时间范围：超过 90 天被拒绝；切换范围后摘要、图表、表格一致刷新。
- [x] AC9 性能：本机按 2 万用户、2 千活跃造数，总览、列表、客户详情接口在 90 天范围下响应 < 1s。
- [x] AC11 标签与邀请列表：有 `team_access` 时显示「邀请 | 团队消费」标签、原入口链接移除；邀请列表显示昵称列，搜索昵称/完整邮箱命中第 100 名以后的直属用户，邮箱前缀与通配符不命中；任命/取消后列表与任命计数刷新。
- [x] AC10 后端 gofmt / 单元 / 集成测试，前端 typecheck / lint / i18n / vitest / build 全部通过；本机 e2e 截图验证三个层级页面。

## Out of Scope

- 导出 CSV、侧边栏菜单、自动刷新 / 推送。
- 客户余额、充值金额、订阅消费。
- 改动现有邀请返利页的邀请列表与任命功能。
- 管理端查看某代理视角的页面。
